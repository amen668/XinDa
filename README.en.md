**XinDa（信达）** takes its name from Yan Fu's translation triad *信 (fidelity) · 达
(readability) · 雅 (elegance)*: **fidelity first, full-text readability next**. The
framework targets full-text machine translation and quality evaluation of scientific
papers. It organizes three related tasks:

- **Usage and costs:** translation calls in the bidirectional input comparison cost
  approximately ¥0.033–0.044 per paper at reference rates. These estimates are not bills
  and exclude additional checks, format conversion and professional human review.
- **Structural protection:** placeholder substitution and restoration protect selected
  elements. Preservation depends on coverage, intact placeholders and reconstruction;
  the Chinese validation found omissions in superscript and subscript protection.
- **Quality checks:** factual verification, quality scores and gating organize automatic
  refinement and prioritize human review. Unflagged units are not verified correct;
  professional review of the complete translation remains necessary. Human time savings
  have not been established.

The framework handles **JATS XML** and **XML generated by the LaTeXML conversion tool**,
supporting Chinese-journal zh→en and arXiv en→zh workflows. PDF-only papers cannot enter
this pipeline directly.

## Research data and offline reproduction

The [November 2026 reproducibility package](research/revision_20261115/README.md) contains
source code, saved inputs and outputs, prompts, attribution, checksums and instructions
for recalculating results without model calls. Its datasets serve distinct purposes:

| Dataset | Sample | Purpose |
|---|---|---|
| Bidirectional input comparison | 25 Chinese and 92 English papers; a shared 15-paper English subset for raw XML | Structure and estimated translation-call costs |
| Chinese structural validation | 50 papers, including the original 25 | Structure within translation-covered regions |
| Chinese-source proposition checks | 50 pairs from 31 papers | Controlled checks against constructed labels, without an independent expert gold standard |
| English-to-Chinese modified examples | 40 pairs from 34 distinct source passages | Exploratory responses; 85% is an anomaly-flagging proportion, not error-detection accuracy |
| Quality-gate records | 10 papers, 2230 units | 747 triggered the gate, 677 were refined, 376 remained flagged |
| Historical batch snapshot | 1656 tasks, 1560 papers with successful outputs | Anonymous operational and structural statistics; historical full translations are excluded |

Recalculation from saved outputs does not reproduce past model calls. Some historical
runs lack complete request metadata and immutable model versions. New model calls need
service credentials and may incur charges. See the package for the evidence boundaries.

## Architecture at a glance

A 13-stage, resumable pipeline (Postgres records state; re-running the same `job_id`
auto-resumes from the last checkpoint):

```
Acquire → Convert → Extract → FactExtract → GlossaryBuild → FirstPassTranslate
  → FactVerify → CrossDocFactVerify → Refine → Coherence → ApplyXML → Render → Evaluate
```

Evaluation suite (`xinda/evaluation/`): structural fidelity PPA/MFR (with order-sensitive
variants), factual fidelity FPS / fact-traps, the cross-lingual comparison verifier,
COMET-Kiwi / xCOMET neural QE, QA comprehension (RCS), terminology consistency (TCR),
LLM judges (RUBRIC-MQM / G-Eval) + judge meta-evaluation, cost accounting, and gated
human-review triage.

## Quick start

Docker is recommended (host-side LaTeXML/torch setup is fiddly):

```bash
cp .env.example .env        # set POSTGRES_PASSWORD, DATABASE_URL and DASHSCOPE_API_KEY
docker compose up -d db     # Postgres; schema applied automatically
docker compose run --rm app python -m xinda.cli.translate_smoke 2503.15129 zh
# Neural QE needs a GPU, in the separate qe service:
docker compose run --rm qe python -m xinda.cli.neural_qe <job_id>
```

DB-free single-paper JATS translation and structural benchmark:

```bash
python -m xinda.cli.jats_translate <jats.xml> en          # translate a whole JATS paper
python -m xinda.cli.jats_benchmark --corpus-dir corpus/jats_zh2en --lang en \
    --format jats --systems contract,naive --out-dir results/demo
```

See `xinda/cli/` for more entry points (corpus building, license filtering, the
benchmark matrix, judge meta-evaluation, etc.).

## Configuration

`xinda/config.py` (Pydantic `BaseSettings`, reads `.env`; see `.env.example`). No
hard-coded secrets. Key variables: `DASHSCOPE_API_KEY`, `DATABASE_URL`,
`LATEXMLC_PATH` / `LATEXMLPOST_PATH` / `MAGICK_PATH`.
Docker's database and application services share `POSTGRES_PASSWORD`, configured in
your local `.env`. This Docker template requires a URL-safe password. For direct connections
from the host, encode special characters in `DATABASE_URL`. Changing an environment variable does not rotate an existing
database volume's password.

## Data & licensing

The bidirectional input comparison uses **CC0 / CC-BY / CC-BY-SA** papers; the 50-paper
Chinese validation uses **CC-BY** papers. Source attribution and licenses are recorded
per article. Historical task records lack complete source-version licensing records,
so only anonymous aggregate statistics are published for that snapshot. The MIT code
license does not relicense third-party papers or translations. See [`DATA.md`](DATA.md).

[`examples/`](examples/README.md) retains bilingual renderings, historical results and
corpus manifests. Additional experiment evidence is organized under `research/`.
Local corpora, workspaces, logs, credentials, manuscripts, reviewer materials and review
scratch files are not published wholesale.
